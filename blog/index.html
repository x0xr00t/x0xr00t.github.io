01. Parameter Expansion – Sed Has Left the Building

Let's start with something innocent.

#!/usr/bin/env bash

name="x0xr00t"
host="kali-2026"
path="/usr/local/bin/sl0ppy"

printf '%s\n' "${name}"
printf '%s\n' "${host}"
printf '%s\n' "${path}"

Nothing special, right?

Now let's start removing things without calling external utilities.

file="/var/log/auth.log"

echo "${file##*/}"
echo "${file%/*}"

Output:

auth.log
/var/log

Congratulations. You've just replaced a couple of unnecessary subprocesses with Bash doing what Bash was already capable of doing.

The operators:

${VAR#pattern}     # Remove shortest matching prefix
${VAR##pattern}    # Remove longest matching prefix
${VAR%pattern}     # Remove shortest matching suffix
${VAR%%pattern}    # Remove longest matching suffix

And because apparently we can't leave things alone:

URL="https://example.org:8443/api/v1/users?id=42"

HOST="${URL#*://}"
HOST="${HOST%%/*}"
HOST="${HOST%%:*}"

printf '%s\n' "$HOST"

Output:

example.org

No cut. No awk. No sed.

Just parameter expansion doing the dirty work.

02. String Replacement – The Lazy Operator's Toolkit

string="linux-linux-linux"

echo "${string/linux/KALI}"
echo "${string//linux/KALI}"

Output:

KALI-linux-linux
KALI-KALI-KALI

One match versus all matches.

Want to remove every hyphen?

string="malware-analysis-research"

echo "${string//-/}"

Output:

malwareanalysisresearch

Want to replace an extension?

file="payload.bin"

echo "${file%.bin}.safe"

Output:

payload.safe

And yes, this is all built into Bash.

03. Case Conversion – Uppercase Everything

name="sl0ppyroot"

echo "${name^^}"
echo "${name^}"

Output:

SL0PPYROOT
Sl0ppyroot

Lowercase:

name="SL0PPYROOT"

echo "${name,,}"
echo "${name,}"

Output:

sl0ppyroot
sL0ppyroot

These transformations are available in Bash 4 and later.

If you're wondering why your old POSIX shell suddenly starts throwing a tantrum, that's because these aren't POSIX parameter expansions.

04. Substring Expansion – Slice It, Dice It

string="0123456789"

echo "${string:0:4}"
echo "${string:4:3}"
echo "${string: -3}"

Output:

0123
456
789

The syntax:

${VARIABLE:OFFSET:LENGTH}

Negative offsets count backward from the end.

And yes, that space before -3 matters.

Bash isn't a mind reader.

05. Indirect Expansion – Variables Inside Variables

Now we're getting somewhere.

TARGET="192.0.2.10"
NAME="TARGET"

echo "${!NAME}"

Output:

192.0.2.10

The variable NAME contains the name of another variable.

${!NAME} retrieves its value.

Let's make it unnecessarily complicated:

A="B"
B="C"
C="KALI"

echo "${!A}"
echo "${!B}"

Output:

C
KALI

One variable points to another, which points somewhere else.

Basically shell-based family drama.

06. XOR Encoding – Because Plain Text Is Apparently Too Mainstream

Now let's move into something a little more interesting.

XOR encoding.

First, a small reality check:

XOR encoding is not encryption.

It's a reversible transformation. A predictable XOR key provides no meaningful confidentiality.

Still, it's useful for understanding byte transformations, encoding schemes and how shell operators can be combined with external interpreters.

Let's use a harmless demonstration command:

printf '%s\n' 'x0xr00t says hello'

We'll XOR every byte using the key 0x23, then Base64-encode the resulting bytes.

Encoding – One-liner

python3 -c 'import base64,sys; print(base64.b64encode(bytes(b ^ 0x23 for b in sys.argv[1].encode())).decode())' "printf '%s\n' 'x0xr00t says hello'"

Output:

U1FKTVdFAwQGUH9NBAMEWxNbURMTVwNQQlpQA0tGT09MBA==

There you go.

A harmless command transformed into a Base64 representation of XOR-encoded bytes.

Decoding – One-liner

Now let's reverse the operation:

python3 -c 'import base64,sys; print(bytes(b ^ 0x23 for b in base64.b64decode(sys.argv[1])).decode())' 'U1FKTVdFAwQGUH9NBAMEWxNbURMTVwNQQlpQA0tGT09MBA=='

Decoded output:

printf '%s\n' 'x0xr00t says hello'

And we're back where we started.

The same XOR key reverses the transformation because XOR has the property:

(A XOR K) XOR K = A

Remember: Base64 is only a representation layer. XOR is the reversible transformation.

07. Command Substitution – The $() Rabbit Hole

Now comes the part where people start looking at their terminal differently.

Command substitution:

RESULT="$(printf '%s' 'x0xr00t')"

echo "$RESULT"

Output:

x0xr00t

The shell executes the command inside $() and substitutes its output.

You can nest it:

echo "$(printf '%s' "$(printf '%s' 'sl0ppyRoot')")"

Output:

sl0ppyRoot

Why?

Because apparently one layer of command substitution wasn't enough.

Decoding directly into a shell command

Let's combine our XOR decoder with command substitution.

For this demonstration, the decoded command only prints a harmless message.

bash -c "$(python3 -c 'import base64,sys; print(bytes(b ^ 0x23 for b in base64.b64decode(sys.argv[1])).decode())' 'U1FKTVdFAwQGUH9NBAMEWxNbURMTVwNQQlpQA0tGT09MBA==')"

Output:

x0xr00t says hello

What happened?

  1. Python decoded the Base64 data.
  2. XOR reversed the byte transformation.
  3. Python printed the reconstructed command.
  4. $() captured that output.
  5. bash -c executed the resulting command.

One-liner.

Multiple operations.

And a very good reason to understand what you're actually executing.

Security note: This demonstrates command reconstruction and execution, not a security feature. Never pass untrusted decoded strings into bash -c, eval or another command interpreter. XOR does not make a payload safe, trustworthy or undetectable.

08. Arrays – Because One Variable Wasn't Enough

hosts=("localhost" "192.0.2.10" "example.org")

echo "${hosts[@]}"
echo "${hosts[1]}"
echo "${#hosts[@]}"

Output:

localhost 192.0.2.10 example.org
192.0.2.10
3

Slice them:

echo "${hosts[@]:1:2}"

Output:

192.0.2.10 example.org

And please, for the love of everything that is still functioning on your Linux installation, quote your array expansions when iterating:

for host in "${hosts[@]}"; do
    printf '[+] %s\n' "$host"
done

Unquoted expansions can introduce word splitting and pathname expansion.

Your array deserves better.

09. The One-Liner Combos – Terminal Abuse Championship

Now let's combine some of the things we've covered.

Combo A – Replace, uppercase, slice

x="linux-security-research"

x="${x//-/ }"
x="${x^^}"

echo "${x:0:12}"

Output:

LINUX SECURI

Combo B – Remove a path and change the extension

f="/opt/sl0ppy/report.log"

f="${f##*/}"
echo "${f%.log}.txt"

Output:

report.txt

No external utilities.

No subprocesses.

Just Bash.

Combo C – Nested command substitution

printf '[%s]\n' "$(printf '%s' "$(printf '%s' 'x0xr00t' | tr '[:lower:]' '[:upper:]')")"

Output:

[X0XR00T]

Yes, we used tr here.

Sometimes the point is to demonstrate composition, not pretend every utility is forbidden.

Combo D – XOR transformation in a single expression

python3 -c 'print(bytes(b ^ 0x23 for b in b"x0xr00t").hex())'

This produces the hexadecimal representation of the XOR-transformed bytes.

Reverse it:

python3 -c 'print(bytes(b ^ 0x23 for b in bytes.fromhex("5b11")) .decode())'

Replace the hexadecimal example with the actual encoded output generated by the first command.

Same key.

Same operation.

Original bytes restored.

10. Final Boss – The Shell Is Not Your Interpreter's Babysitter

Let's finish with something that combines a few Bash features without turning the whole thing into an unreadable maintenance nightmare.

#!/usr/bin/env bash

set -u

declare -A INFO=(
    [USER]="x0xr00t"
    [HOST]="kali-2026"
    [MODE]="READ-ONLY"
)

for key in "${!INFO[@]}"; do
    printf '[%s] %s\n' "$key" "${INFO[$key]}"
done

This uses:

  • Associative arrays
  • Parameter expansion
  • Array key enumeration
  • Built-in formatting
  • No external text-processing tools

And yes, associative arrays are Bash-specific.

11. Terminal Compatibility – Know Your Shell

Not every shell speaks the same language.

Here's a quick compatibility overview:

FeatureBash 5.xZshDashBusyBox ashFish
Default-value expansionYesYesYesYesDifferent syntax
Prefix/suffix removalYesYesYesYesDifferent syntax
Global replacementYesYesNoVersion-dependentDifferent syntax
Uppercase expansionYesDifferent syntaxNoNoDifferent syntax
Substring expansionYesYesNoVersion-dependentDifferent syntax
Associative arraysYesYesNoLimitedNative lists

Don't assume /bin/sh is Bash.

On Debian and Kali installations, /bin/sh is commonly Dash.

Your interactive terminal may happily execute a script that fails when launched through /bin/sh.

And then you spend the next 45 minutes wondering why your perfectly innocent script has decided to become a crime scene.
